# 项目文档模板

一套能撑住三个月后的项目文档，外加一个让 AI 编码助手遵守它的入口文件。

核心是 `docs/decisions/`：把「当时为什么选它、否掉了哪些方案、各是因为什么」单独存下来。代码和聊天记录都留不住这些东西——三个月后你只会看到用了 PG，不会知道自己为什么没选 SQLite，更不知道为什么不该改成别的。

附带解决第二件事：`docs/NOW.md` 承载当前上下文，新开一次会话不用重讲进度。

## 用法

把仓库根的 `docs/` 和 `AGENTS.md` 拷进新项目根目录，然后开始写代码：

```bash
cp -r <模板路径>/docs      <新项目>/docs
cp    <模板路径>/AGENTS.md <新项目>/AGENTS.md
```

```powershell
Copy-Item -Recurse <模板路径>\docs      <新项目>\docs
Copy-Item          <模板路径>\AGENTS.md <新项目>\AGENTS.md
```

没有依赖，不需要 Node，全是 Markdown。

## 两个文件各自管什么

| 文件 | 作用 |
| --- | --- |
| [AGENTS.md](AGENTS.md) | 放在项目根，助手新会话会自动读到：先读 `docs/NOW.md` 再动代码，外加四条硬规则 |
| [docs/WORKFLOW.md](docs/WORKFLOW.md) | 给人看的流程：从领需求到提交，每一步该动哪个文档 |

AGENTS.md 只做入口，不复述规则正文。细节仍然只在 `docs/` 里维护一份，改流程时不用两头动。

## 结构

```
AGENTS.md
docs/
├── decisions/     # ADR 架构决策记录：背景、决策、备选方案与否决理由、影响、复查条件
├── design/        # 定论设计：模块、数据库、接口、架构图
├── refactor/      # 重构专项：现状问题、新旧对比、迁移步骤、回滚、风险
├── templates/     # 6 份模板：adr / prd / design / refactor / milestone / incident
├── INDEX.md       # 总目录：每篇文档一行「链接 + 状态 + 说明」
├── NOW.md         # 当前视图：在做什么、卡在哪、下一步、断点状态
├── projectneed.md # 需求 / PRD：只有需求层
├── WORKFLOW.md    # 开发流程与文档更新规则
└── writing-rules.md # 书写规范：分层、状态行、什么能改什么不能改
```

## 拷过去之后第一轮填什么

1. `projectneed.md` — 目标、做/不做、带验收线的功能需求。**只写需求层。**
2. `NOW.md` — 在做什么、下一步、断点，以及 `> 更新：` 时间。
3. 如果手上已经有选型结论，建第一条 `decisions/0001-<短名>.md`。

**不要**为了让目录"看起来完整"去造空的 design/ 文档，`writing-rules.md` 第 9 节明确禁止。填完把 `<尖括号占位>` 清干净，那些内容是给使用者看的，不该留在交付文档里。

## 三条最容易被违反的规则

细节在 [docs/writing-rules.md](docs/writing-rules.md)，这里只列最要紧的：

1. **有方案被否掉，就当场记一条 ADR**，哪怕正文只有十行。隔天再补，写下来的只有结论，没有理由。
2. **已生效的 ADR 不改正文。** 推翻它 = 新开一条 + 把旧的标 `已废弃（被 NNNN 取代）`。改了就不是决策记录，是事后解释。
3. **PRD 只写需求层。** 技术栈、表结构、接口契约、排期都不进 `projectneed.md`——架构约束要保留，但剥掉实现名翻译成产品语言：写「换机能完整找回全部数据」，不写「用 PG 做主存储」。

## 目录清单怎么维护

没有脚本。新增/改名/删除任何 md，手工改 `docs/INDEX.md` 的清单表：一行「链接 + 状态 + 说明」，后两项照抄该文档头部的 `> 状态：` 和 `> 摘要：`。这就是每份文档头部必须有那两行的原因。

## 裁剪

结构是约定不是强制。项目小可以只留 `decisions/` + `NOW.md` + `INDEX.md`，其余目录等真有内容再建。
